🐚 Terminal Shell Upgrade: ZSH & Oh-My-Zsh

This section explains what ZSH and Oh-My-Zsh are, why they were considered, and whether they are required for the VPS.

🧠 What is a Shell?

A shell is the program that reads your commands (ls, cd, python) and executes them.
Examples of common shells: - bash (default on many Linux systems) - zsh (modern alternative)

🐚 What is ZSH?

ZSH (Z Shell) is a modern replacement for bash. It does the same job, but with better usability.

  • Smarter auto-completion
  • Better command history
  • Cleaner terminal prompt
  • Highly customizable

ZSH is commonly used in WSL and modern Linux development environments.

🎨 What is Oh-My-Zsh?

Oh-My-Zsh is NOT a shell.
It is a framework that runs on top of ZSH.
Conceptual analogy: ZSH = Operating system Oh-My-Zsh = Launcher + plugins + themes
  • Git branch shown automatically
  • Command suggestions while typing
  • Syntax highlighting (errors in red)
  • Themes for better readability

❓ Is ZSH / Oh-My-Zsh Required?

  • NOT required for the server to function
  • Purely improves developer experience
  • No impact on Django, MySQL, or Nginx

🛡️ Is It Safe on a VPS?

  • Lightweight
  • No performance overhead
  • Affects only the terminal UI
  • No security risk

🤔 Decision Logic

If simplicity is the goal → bash is enough If WSL-like comfort is the goal → ZSH + Oh-My-Zsh

🔍 How to Check Active Shell

echo $SHELL
  • /bin/bash → bash
  • /usr/bin/zsh → zsh

🏁 Final Recommendation

Since the goal was to replicate a WSL-like development experience, installing ZSH + Oh-My-Zsh is recommended.

It improves productivity and comfort without affecting server stability.

🐳 Docker Usage Decision: Docker CLI vs Docker Desktop

This section documents the decision to use Docker CLI instead of Docker Desktop, and explains why this is the correct and industry-standard approach for a VPS-based workflow.

🔍 Simple Comparison

Docker Desktop
• GUI application
• Heavy (RAM + CPU)
• Runs hidden VM on Windows
• License required in some cases
• Overkill for terminal users
Docker CLI (Docker Engine)
• Terminal-based
• Lightweight
• Free & open-source
• Runs natively on Linux
• Standard for servers & VPS

🧠 Key Industry Fact

On Linux servers and VPS environments, Docker Desktop is NOT used.
Professionals use Docker CLI + Docker Engine.

✅ Where Docker CLI Works Perfectly

  • Ubuntu VPS (like this server)
  • WSL-style development environments
  • CI/CD pipelines
  • Production servers

⚠️ Important Clarification: VPS vs Windows

🟢 On the VPS (Ubuntu 24.04)

  • Docker CLI only
  • No Docker Desktop required
  • Best practice

🟡 On Windows (Local Machine)

  • Docker CLI alone cannot run containers
  • Requires Docker Desktop OR
  • WSL2 + Docker Engine inside WSL

⭐ Recommended Setup (Chosen Approach)

  • VPS runs Docker containers
  • Docker CLI installed on VPS
  • Windows uses VS Code Remote SSH
  • No Docker Desktop needed

  expiresAt: ISODate,
  active: true,

  createdAt: ISODate

  • Coupons do not stack

Coupon Rules (Strict)

  • One coupon per user (ever)
  • Coupons do not auto-renew
  • Coupons expire globally
  • usedCount < maxRedemptions
  • Coupon users are treated the same as paid users for quota

These rules prevent farming, infinite free usage, and quota abuse.

Per-User Monthly AI Quota (Atlas)

AI_QUOTA_PER_MONTH = $5.00

This quota applies equally to: Paid users, Coupon users, Admin-granted users.

There are no exceptions.

AI Usage Tracking Model

AiUsage {
  userId,
  month: "YYYY-MM",
  provider,   // gemini | groq
  cost,
  createdAt
}

Monthly usage is calculated by summing costs for the active month bucket.

Hard Stop Logic (Mandatory)

IF totalCostThisMonth >= 300
  → reject request
  → DO NOT route to any AI
  • No fallback
  • No downgrade
  • No partial response

This guarantees zero overspend.

Monthly Reset Strategy

Atlas uses a lazy reset strategy.

  • Usage stored by YYYY-MM
  • New month = new bucket
  • No cron jobs required

This approach is simple, safe, and production-proven.

Atlas Request Contract

  "text": "..."
}

Atlas validation order:

IF aiEnabled !== true → reject
IF now > aiExpiresAt → reject
IF monthlyCost >= 300 → reject
ELSE → route request

Atlas never checks payment method, coupon type, or plan name.

🤖 Atlas Agent — Context-Aware AI Agent

Memory-backed, multi-provider agent system

Three-Layer Memory Model

  • Session Memory — Short-lived conversation context (30-min TTL, MongoDB TTL index)
  • User Profile Memory — Persistent preferences: skill level, tech stack, goals
  • Knowledge Memory — Saved summaries, decisions, notes, insights

Agent Pipeline

  1. Receive message + session context
  2. Load/create session (AgentSession model)
  3. Load user profile (UserProfile model)
  4. Classify intent via fast Groq call
  5. Select provider: Groq for quick answers, Gemini for deep reasoning
  6. Retrieve relevant knowledge by tag matching
  7. Build enriched prompt with full context
  8. Call selected provider
  9. Update session with new exchange
  10. Optional profile update detection (every 5th turn)

API Endpoints

Endpoint Purpose
POST /ai/agentMain agent endpoint
GET/DELETE /ai/agent/session/:idSession management
GET/PATCH/DELETE /ai/agent/memory/profileUser profile CRUD
GET/POST/DELETE /ai/agent/memory/knowledgeKnowledge CRUD

Provider Routing

  • Gemini: explain, plan, compare, summarize, research
  • Groq: quick_answer, debug, clarify

The user never chooses the provider — Atlas Agent decides automatically based on intent classification.
