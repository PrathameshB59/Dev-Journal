The idea is simple:

  • Use Together AI by default for most requests
  • Fallback to OpenAI only when higher quality is required

This avoids unnecessary cost while preserving output quality.

  • Provider: Together AI
  • Used for ~90% of requests
  • Optimized for cost and speed

Typical use cases:

  • Summaries and rewrites

  • VPS troubleshooting notes
  • Markdown cleanup

Premium / Fallback Mode

  • Provider: OpenAI
  • Used selectively
  • Consumes budget faster

Triggered when:

  • Explanation complexity is high
  • Architectural reasoning is required
  • Output quality is critical
  • Default provider response is insufficient

This path is intentionally limited to protect the ₹300/month quota.

    User request

🧠 Atlas AI – Multi-Provider Architecture Decision

Final Verdict

Atlas intentionally uses a multi-provider AI architecture instead of relying on a single AI vendor.

This approach delivers quality, speed, privacy, and cost control simultaneously.

Atlas is designed as a smart AI router, not a simple API wrapper.

Why This Combination Works

Each AI provider is selected for a specific strength. Atlas routes requests based on use case, not preference.

Together AI — Daily Workhorse

  • Default provider for most AI requests
  • Handles ~70–80% of usage
  • Optimized for documentation, summaries, and journaling
  • Uses open-source models
  • Low cost and no vendor lock-in

Together AI is the backbone of Atlas for everyday workloads.

Groq — Instant Help Path

  • Used for fast, short responses
  • Ideal for error explanations and quick questions
  • Near-instant latency
  • Extremely low cost

Groq provides a terminal-like experience for instant feedback.

OpenAI — Premium Reasoning Layer

  • Used only for complex or high-importance requests
  • Best reasoning and explanation quality
  • Consumes budget faster
  • Strictly rate-limited

OpenAI is reserved for situations where quality matters more than cost.

Why a Single Provider Is Not Enough

  • Only OpenAI → Excellent quality but expensive and overkill
  • Only Together AI → Cheap and private but weaker for deep reasoning
  • Only Groq → Fast and cheap but unsuitable for long explanations

A single-provider setup forces trade-offs. A multi-provider setup removes them.

Industry-Standard Pattern

  • Simple tasks routed to low-cost models
  • Complex tasks routed to premium models
  • Strict budget enforcement
  • Provider complexity hidden from users

Atlas follows the same pattern used by mature developer tools.

Operational Considerations

  • Slightly higher backend logic complexity
  • Multiple API keys (one-time setup)
  • No risk of cost surprises due to hard limits

These trade-offs are intentional and manageable.

Design Conclusion

Together AI + Groq + OpenAI is not over-engineering. It is a deliberate, cost-aware architecture choice.

This design keeps Atlas fast, affordable, private, and future-proof.

Before finalizing the name Atlas, multiple naming directions were explored to ensure the system’s identity matched its role as infrastructure rather than an application feature.

Names were evaluated for longevity, neutrality, and suitability for backend, VPS, API, and CLI usage.

🛡 Infra / System Guardian Names

Quiet, reliable, background services — similar to OS or VPS components.

  • Sentinel — watcher / guardian
  • Aegis — shield / protection
  • Warden — system guard
  • Custodian — caretaker of systems
  • Beacon — signal and guidance
  • Watchtower — observability-focused
  • Gatekeeper — access and routing control
  • Bastion — stronghold / security-oriented

Suitable when the AI feels like part of the operating environment.

🌍 Core / Backbone / Universal Names

Central services used by many projects.

  • Atlas — backbone / carrier
  • Pillar — structural support
  • Keystone — central locking component
  • Spine — main support structure
  • Nexus — connection point
  • Core — central engine
  • Anchor — stability and grounding
  • Foundation — base layer

Best suited for shared infrastructure rather than end-user branding.

🔁 Routing / Intelligence Layer Names

Names that closely match the AI-router architecture.

  • Relay — request forwarding
  • Conductor — orchestration
  • Switchboard — connection routing
  • Router — literal and explicit
  • Dispatcher — task distribution
  • Broker — intermediary service
  • Mediator — decision layer
  • Signal — request and response flow

⚙️ Engineer / Builder-Oriented Names

Toolmaker and developer productivity tone.

  • Forge
  • Smith
  • Assembler
  • Builder
  • Engineer
  • Craft
  • Workbench
  • Workshop

☁️ Cloud / Modern Tech Names

Clean, SaaS-friendly, and modern.

  • Nimbus
  • Cirrus
  • Stratus
  • Helix
  • Vector
  • Pulse
  • Flux
  • Orbit

🧠 Knowledge / Documentation-Oriented Names

Suitable for journaling, documentation, and structured knowledge.

  • Sage
  • Archivist
  • Librarian
  • Mnemonic
  • Logos
  • Oracle (intentionally avoided for being dramatic)
  • Index
  • Scholar

Rejected Naming Patterns

  • Pop-culture references
  • Vendor-tied names
  • “Assistant” or chatbot-style branding
  • Trendy or short-lived naming patterns

The system is infrastructure, not a sidekick.

Refined Shortlist

  1. Sentinel — strongest guardian identity
  2. Relay — best architectural match
  3. Atlas — safest and most universal
  4. Nexus — strong central hub metaphor
  5. Aegis — security-focused alternative
  6. Conductor — orchestration-centric
  7. Archivist — strong documentation tie-in

Name Validation Heuristic

“<NAME> downgraded OpenAI due to budget limit.”

If the sentence sounds natural, the name is suitable for infrastructure.

🔒 Atlas AI – Name Lock & Identity

Final Name Confirmation

The AI system is officially named Atlas.

This decision is final and treated as part of the system architecture. The name will not be changed going forward.

Why the Name “Atlas”

  • Universal — shared across all projects
  • Backbone — infrastructure-level, not a feature
  • Quiet intelligence — reliable, non-intrusive
  • Future-proof — suitable for API, CLI, UI, SaaS, or open-source

Atlas is designed to support systems without drawing attention to itself.

Identity Lock (Non-Negotiable)

  • Project name: Atlas
  • Role: Universal AI Core / Internal AI Platform
  • Scope: All projects under ~/dev/projects/
  • Monthly AI budget: ₹300 per user (hard cap)

Consistency is critical for long-term maintainability.

Directory Naming Standard

    ~/dev/projects/
    ├── atlas/
    │   ├── src/
    │   ├── providers/
    │   ├── budget/
    │   ├── data/
    │   ├── package.json
    │   ├── .env
    │   └── README.md
    ├── Dev-Journal/
    ├── ShopEase/
    └── other-projects/
  • Use atlas (lowercase) for folders and paths
  • Use Atlas (capitalized) in documentation, UI, and logs

Operational Tone Guide

Atlas communicates in a calm, factual, infrastructure-oriented manner.

Examples:

    Atlas: OpenAI budget exhausted, routing disabled
    Atlas: Request routed to Groq (fast path)
    Atlas: Monthly AI usage at 82%

No conversational tone, no humor, no emojis. Atlas behaves like infrastructure.

Identity Statement

Atlas is a universal AI core service designed to support multiple projects from a single, centralized intelligence layer. It prioritizes cost control, provider flexibility, and long-term maintainability.

Post-Naming Execution Plan

  4. Implement the ₹300 per-user budget guard
  5. Add Atlas as a managed PM2 service

Provider integration follows only after the foundation is complete.

👤 Atlas AI – Per-User Budget Enforcement

Problem Identification

Atlas was initially considered with a single global monthly AI budget. This approach breaks immediately once the system is exposed to multiple authenticated users.

In a public application, a single user could exhaust the entire AI budget, impacting all other users.

This issue was identified early and corrected at the architecture level.

Correct Mental Model

Atlas must treat AI usage as a per-user resource, not a shared global pool.

Each authenticated user receives an isolated AI allowance.

  • ❌ Not per project
  • ❌ Not per server
  • ❌ Not per API key
  • ✅ Per authenticated user

This aligns naturally with existing JWT authentication and RBAC.

Final Budget Strategy

Atlas enforces a strict ₹300 per user per month AI budget.

  • Fair and predictable for users
  • Scales safely for public access
  • No cross-user impact
  • No surprise billing

Per-User Budget Breakdown

Provider Monthly Limit (per user)
Together AI ₹150
Groq ₹50
OpenAI ₹100
Total ₹300 / user / month

One user reaching their limit has no effect on others.

Updated Architecture Flow

    User (JWT Authenticated)
            ↓
    Dev-Journal Backend API
            ↓
    Atlas AI Core
            ↓
    Per-User Budget Check
            ↓
    AI Provider (if allowed)

Atlas must receive a userId with every AI request.

User-Aware Request Contract

Every AI request sent to Atlas must include the user identity. 

    {
      "userId": "mongo_user_id_here",
      "action": "summarize",
      "text": "..."
    }
  • Atlas does not manage authentication
  • Atlas trusts Dev-Journal JWT validation
  • Atlas only enforces budget and routing

Usage Tracking Model

AI usage is tracked per user and per calendar month. 

    AiUsage {
      userId,
      provider,     // together | groq | openai
      cost,
      month,        // YYYY-MM
      createdAt
    }

Monthly totals are computed by summing usage for the active month.

Behavior When Limit Is Reached

  • OpenAI requests are blocked
  • Groq requests are blocked
  • Together AI may optionally show a warning
  • AI access resumes automatically next month

Clear feedback prevents user frustration.

Global Safety Net

In addition to per-user limits, Atlas enforces a global safety cap to protect system-wide costs.

Scope Limit
Per user ₹300 / month
Global Atlas ₹3,000 / month

If the global limit is reached, premium providers are temporarily disabled.

Design Summary

Atlas enforces AI usage limits per user rather than globally. Each user has an isolated monthly allowance that resets automatically.

This design supports public usage, paid plans, coupons, and future upgrades without architectural changes.

💳 Atlas AI – Monetization & Access Model

Final Rule (Locked)

Dev-Journal operates under a strict separation between core application features and AI-powered features.

All Dev-Journal features are free.
AI features are paid — ₹300 per user per month.

What Is Free

  • CRUD journal entries
  • File explorer interface
  • Dashboard and statistics
  • Authentication and authorization
  • RBAC and role management
  • Exports and basic tooling

Core productivity features are never gated behind payment.

What Is Paid

  • AI-powered summaries
  • AI explanations and reasoning
  • AI-assisted documentation rewrite
  • AI-based error analysis and help

These features require an active Atlas AI subscription.

Correct Mental Model

Dev-Journal itself is not the paid product.

The paid product is AI access via Atlas. 

    Dev-Journal = Free Product
    Atlas AI    = Paid Add-on

Dev-Journal simply consumes Atlas as a service.

AI Subscription Plan

  • Price: ₹300 per month
  • Scope: Per user
  • Billing: Manual initially (Razorpay / Stripe later)
  • Reset: Monthly

Pricing is intentionally simple and predictable.

User States

State Meaning
aiEnabled = false Free user (no AI access)
aiEnabled = true Paid user (₹300 plan)

This flag is stored in the Dev-Journal database, not in Atlas.

Access Control Flow

    User
      ↓
    Dev-Journal Backend
      ↓
    Check aiEnabled flag
      ↓
    Atlas AI (budget enforcement)
      ↓
    AI Providers

Atlas never decides who is paid. It only enforces usage rules.

AI Request Contract

Every AI request must explicitly declare whether AI access is enabled. 

    {
      "userId": "abc123",
      "aiEnabled": true,
      "action": "summarize",
      "text": "..."
    }

Requests with aiEnabled !== true are rejected immediately.

Budget Enforcement for Paid Users

Paid users receive a strict monthly AI allowance.

Provider Monthly Limit
Together AI ₹150
Groq ₹50
OpenAI ₹100
Total ₹300 / month

Behavior When Limit Is Reached

  • AI requests are blocked immediately
  • No fallback or partial responses
  • No overuse beyond ₹300
  • Access automatically resets next month

This guarantees zero surprise billing.

User Experience Expectations

Free user:

  • AI buttons visible but disabled
  • Clear message: “AI features cost ₹300/month”

Paid user:

  • AI buttons enabled
  • Visible usage meter (e.g. ₹180 / ₹300)

User at limit:

  • AI buttons disabled
  • Message: “AI limit reached. Resets next month.”

Security & Abuse Prevention

  • All AI calls require JWT-authenticated backend requests
  • User identity is always known
  • RBAC already enforced upstream
  • Atlas never accepts direct browser calls

This prevents budget abuse and unauthorized access.

Design Summary

Dev-Journal is free for everyone.
Atlas AI is a paid add-on costing ₹300 per user per month.
Dev-Journal controls access.
Atlas enforces budget and routing.

This model is simple, scalable, and production-safe.

🎟 Atlas AI – Coupon & Free Trial System

Purpose

Atlas supports a coupon-based free trial system to enable user growth without uncontrolled AI spending.

Coupons grant temporary AI access while still enforcing the standard ₹300 per-user monthly budget.

Design Principles

  • Safe by default
  • Abuse-resistant
  • Cost-predictable
  • Future-proof
  • Clear separation of responsibilities

Responsibility Separation

Component Responsibility
Dev-Journal User accounts, subscriptions, coupons
Atlas AI AI access enforcement and budget control
AI Providers Inference only (no business logic)

Atlas never manages users, pricing, or coupons directly.

High-Level Flow (Coupon → AI Access)

    Admin creates coupon
          ↓
    User applies coupon
          ↓
    Dev-Journal validates coupon
          ↓
    AI access enabled for limited duration
          ↓
    Dev-Journal calls Atlas
          ↓
    Atlas allows AI until expiry

Atlas only validates flags and dates; it never decides eligibility.

Coupon Data Model (Dev-Journal)

    Coupon {
      code: "ATLAS-FREE-1M",
      type: "FREE_SUBSCRIPTION",
      durationDays: 30,
      maxRedemptions: 100,
      usedCount: 12,
      expiresAt: ISODate,
      active: true,
      createdBy: adminId
    }

This model enables expiry, redemption limits, and abuse prevention.

User Subscription Fields

    User {
      aiEnabled: true,
      aiPlan: "PAID" | "COUPON",
      aiExpiresAt: ISODate,
      couponUsed: "ATLAS-FREE-1M"
    }
  • Coupons do not stack
  • One coupon per user (lifetime)
  • Access automatically expires

Coupon Rules (Non-Negotiable)

  • One coupon per user (ever)
  • Coupon must be active and not expired
  • usedCount < maxRedemptions
  • Coupons do not auto-renew
  • Coupons cannot be reused by the same user

These rules prevent farming, abuse, and infinite free access.

Atlas Integration Contract

Every AI request sent to Atlas must include access flags and expiry data. 

    {
      "userId": "abc123",
      "aiEnabled": true,
      "aiExpiresAt": "2026-03-05T00:00:00Z"
    }

Atlas validation logic:

    IF aiEnabled !== true → reject
    IF now > aiExpiresAt → reject
    ELSE → allow AI (₹300 budget applies)

Budget Handling for Coupon Users

  • Coupon users receive the same ₹300 monthly AI limit
  • No special quota or bypass
  • Usage resets monthly
  • Coupon duration limits total exposure

Coupon users behave exactly like paid users from Atlas’ perspective.

User Experience Expectations

Free user:

  • AI buttons disabled
  • Prompt to subscribe or apply coupon

Coupon applied:

  • AI features enabled immediately
  • Banner showing expiry date
  • Usage meter visible

Coupon expired:

  • AI access disabled
  • Clear upgrade prompt

Admin Coupon Generation

  • Manual or automatic code generation
  • Configurable duration (e.g. 30 days)
  • Max redemption limits
  • Global expiry date

Example coupon codes:

    ATLAS-FREE-1M
    STACKPILOT-AI
    DEVJOURNAL-TRIAL

Future Extensions

  • Short trials (7 days)
  • Discount coupons
  • Referral-based extensions
  • Student or team plans

All extensions can be added without modifying Atlas core logic.

Final Rules (Locked)

  • One coupon = one user
  • Coupons grant temporary AI access only
  • ₹300 monthly budget is always enforced
  • Atlas remains clean and provider-agnostic
  • Dev-Journal controls eligibility and lifecycle

⚙️ Atlas AI – Dynamic Coupons & Quota Control

Final Goals (Locked)

  • Dynamic coupons
    • Admin can grant 1–6 months of free AI access
    • Duration is configurable per coupon
    • Usage is strictly controlled
  • Hard ₹300 monthly limit per user
    • Once the limit is reached, AI usage stops immediately
    • No overuse
    • No surprise costs
  • Atlas remains universal
    • Dev-Journal manages users, coupons, and plans
    • Atlas only enforces access rules and quotas

Correct Mental Model

Concept Owned By
Subscription (paid / coupon) Dev-Journal
Coupon duration (1–6 months) Dev-Journal
Monthly AI quota (₹300) Atlas

These concerns are intentionally separated and must never be mixed.

Dynamic Coupon Schema (Dev-Journal)

    Coupon {
      code: "ATLAS-FREE-3M",
      type: "FREE_SUBSCRIPTION",
      durationMonths: 3,          // 1–6 months
      maxRedemptions: 100,
      usedCount: 0,
      expiresAt: ISODate,
      active: true,
      createdBy: adminId,
      createdAt: ISODate
    }

Duration is stored in months to align with billing cycles and quota resets.

User Subscription Fields

    User {
      aiEnabled: true,
      aiPlan: "PAID" | "COUPON",
      aiStartedAt: ISODate,
      aiExpiresAt: ISODate,
      couponUsed: "ATLAS-FREE-3M"
    }
  • Coupons do not stack
  • One coupon per user (lifetime)
  • Expiry is calculated dynamically

Coupon Application Logic

    aiExpiresAt = now + durationMonths

No extensions, no stacking, no abuse paths.

Coupon Rules (Strict)

  • One coupon per user (ever)
  • Coupons do not auto-renew
  • Coupons expire globally
  • usedCount < maxRedemptions
  • Coupon users are treated the same as paid users for quota

These rules prevent farming, infinite free usage, and quota abuse.

Per-User Monthly AI Quota (Atlas)

    AI_QUOTA_PER_MONTH = ₹300

This quota applies equally to:

  • Paid users
  • Coupon users
  • Admin-granted users

There are no exceptions.

AI Usage Tracking Model

    AiUsage {
      userId,
      month: "YYYY-MM",
      provider,   // together | groq | openai
      cost,
      createdAt
    }

Monthly usage is calculated by summing costs for the active month bucket.

Hard Stop Logic (Mandatory)

    IF totalCostThisMonth >= 300
      → reject request
      → DO NOT route to any AI
  • No fallback
  • No downgrade
  • No partial response

This guarantees zero overspend.

Monthly Reset Strategy

Atlas uses a lazy reset strategy.

  • Usage stored by YYYY-MM
  • New month = new bucket
  • No cron jobs required

This approach is simple, safe, and production-proven.

Atlas Request Contract

    {
      "userId": "abc123",
      "aiEnabled": true,
      "aiExpiresAt": "2026-06-01T00:00:00Z",
      "action": "summarize",
      "text": "..."
    }

Atlas validation order:

    IF aiEnabled !== true → reject
    IF now > aiExpiresAt → reject
    IF monthlyCost >= 300 → reject
    ELSE → route request

Atlas never checks payment method, coupon type, or plan name.

Admin Coupon Generator

  • Configurable duration (1–6 months)
  • Manual or auto-generated codes
  • Max redemption limits
  • Expiry date
  • Active / inactive toggle

Example codes:

    ATLAS-FREE-1M
    ATLAS-FREE-3M
    ATLAS-FREE-6M

User Experience Behavior

Free user:

  • AI buttons disabled
  • Prompt to subscribe or apply coupon

Coupon user:

  • AI enabled immediately
  • Expiry date clearly shown
  • Usage meter visible

User hits ₹300 limit:

  • AI disabled instantly
  • Message: “Monthly AI limit reached. Resets next month.”

Coupon expires:

  • AI disabled
  • Upgrade prompt shown

Global Safety Net

    GLOBAL_ATLAS_LIMIT = ₹5,000
  • Protects system-wide spending
  • Premium providers disabled if exceeded
  • Application remains online

This protects the operator, not the user.

Final Architecture Summary

Admins can generate adjustable coupons granting 1–6 months of free AI access. Coupon users are treated exactly like paid users, with a strict ₹300 per-month AI quota enforced by Atlas. Once the quota is reached, AI usage stops until the next reset. Dev-Journal manages subscriptions and coupons, while Atlas remains a universal, cost-safe AI core.
